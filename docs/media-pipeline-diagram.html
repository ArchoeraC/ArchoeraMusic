③ 原生模块分工与共享资源 / 边界

重计算下沉到各原生模块，编排与数据留在托管层：
内核（Zig）
解码 / DSP / 元数据探测 / 池调度
FFmpeg / libfft
兜底解码 · 频谱 FFT（Dart ABI）
TagLib++ / Rust / Go
刮削（C++ TagLib+libcurl）· 下载（Rust）· Subsonic（Go）
  • 在线传输：宿主注入（FFmpeg AVIO，回调只消费字节）为回退基线；内核原生 HTTP(S)（kernel/net.zig，2026-10-01）为可选优先——socket/TLS/Range/重定向由内核自持，失败回退宿主 → FFmpeg，ARCHOERA_ERA_NATIVE_HTTP=0 可关闭。
  • 扫描元数据不进池：zk_metadata_open 是同步直桥 → 不占 EraSync 槽；与播放的耦合只是 CPU/内存/磁盘/网络 竞争。
  • 播放池有界：线程数 ≤ max_workers(+1 Master)；`submit` 只发提示、Master 异步补建；满 cap 即拒、积压消失早停。
  • QoS 缺口：全局队列 FCFS、无优先级/无抢占 → 批量可能拖累播放；AS4（播放优先 / 保留 worker / 批量节流）尚未实现。
  • 其它未做：AS2 的 ring 直推与「C 壳 1 会话 1 引擎线程」替换（N4 每路 Reader 缓冲预算已于 2026-09-23 落地）。
ABI 红线：archoera_mediaengine.h 导出 / JSON 协议 / libfft.so / stream.wav|.pcm 不变（P5）； 内核符号 era_ 前缀；系统能力走 app/native/platform 桥接（Dart 不直连平台）。  ·  依据：docs/audio-kernel-zig.md、audio-kernel-expansion-plan.md、engine-master-pool-design.md、kernel/runtime.zig、scanner/{ScannerEngine,KernelMetadata}.cs。
