# 疑难解答（Troubleshooting）

> 面向**使用者**的排障手册：按现象查章节，先看 §0 收集信息。
> 从源码构建 / 打包失败请直接看 [用户自编译手册](user-build-from-source.md)；
> 安全漏洞请按 [SECURITY.md](../SECURITY.md) 走私密渠道，**不要**开公开 Issue。

## 0. 排障三步

1. **确认版本与平台**：设置 →「关于」查看版本号；记下安装方式（deb / rpm / AppImage / Flatpak /
   AUR / Windows 安装包 / macOS `.app` / 源码构建）。
2. **看日志**：默认写在数据目录的 `logs/archoera.log`（见下表），单文件上限 4 MiB，
   到顶会原地截断重写。日志默认开启，可在 设置 →「存储」的缓存区关闭落盘。
3. **可复现地重试一次**：记下「做了什么 → 期望什么 → 实际什么」，附上日志里同一时刻的几行。

### 数据目录与日志位置

| 平台 | 数据目录（含 `logs/`） |
|---|---|
| Linux | `~/.local/share/ArchoeraMusic` |
| macOS | `~/Library/Application Support/ArchoeraMusic` |
| Windows | `%LOCALAPPDATA%\ArchoeraMusic` |

- 可用环境变量 `ARCHOERA_DATA_DIR` 覆盖（迁移 / 便携场景）。
- 需要更详细的日志时，用 `ARCHOERA_LOG_LEVEL=debug` 启动（取值
  `debug` / `info` / `warn` / `error` / `fatal`，默认 `info`）。
- 日志会对 `token` / `cookie` / `password` / `secret` 等敏感键做掩码；附日志前仍建议自己扫一眼。

## 1. 启动与原生库

### 1.1 启动闪退，或提示「未找到 xxx」

应用通过 FFI 进程内加载原生模块（音频引擎、扫描器、刮削器、下载器、Subsonic、索引器、平台桥接）。
打包产物里它们平铺在可执行文件旁的 `native/`（macOS 在 `.app/Contents/native/`）；**源码运行**时
必须先构建这些模块。

- 源码运行：先跑 `bash app/core/build-linux.sh`（Windows 用 `app/core/build_windows.bat`，
  macOS 用 `bash app/core/build-macos.sh osx-arm64`），再 `flutter run`。
- 开发态 / 排障可设 `ARCHOERA_NATIVE_DIR` 指向库目录；单个模块也可用
  `ARCHOERA_AUDIO_ENGINE` / `ARCHOERA_SCANNER_FFI` / `ARCHOERA_INDEXER_FFI` /
  `ARCHOERA_DOWNLOADER_SO` / `ARCHOERA_PLATFORM_BRIDGE` 精确指定。
- 发布包：确认安装目录里的 `native/` 没有被杀毒软件或手工操作删掉。
- **完整性校验失败**（`原生库完整性校验失败：…（manifest 不匹配）`）：打包态会 fail-closed。
  自己替换过 `native/` 里的库时，必须重新生成清单：

  ```bash
  bash app/tool/gen_native_manifest.sh <bundle>/native
  ```

  开发态没有清单时会跳过校验（只记一条 WARN），不会因此启动失败。

### 1.2 全屏提示「vault 二进制校验失败」

说明 `archoera-vault` 不是官方生产构建（被替换 / 损坏 / 混入了测试构建）。应用会**删除异常副本并
拒绝解密**，此时本地凭据可能已暴露。处理：**重新安装官方产物**，不要手工替换 vault 二进制，
也不要从其它版本拷贝。详见 [凭据保险库安全说明](vault-security-notes.md)。

### 1.3 升级后提示「凭据库版本不兼容」

2026-10 的保险库重构移除了旧容器格式，**没有迁移路径**：旧文件只能销毁重建，然后重新登录各平台
（设置 →「存储」→ 安全销毁）。重建前请确认没有正在进行的下载 / 播放任务。

### 1.4 Linux 启动缺依赖

发布包声明了 GTK / D-Bus / SQLite / OpenSSL 等运行库。若启动即报共享库缺失，按发行版补齐：

```bash
# Debian / Ubuntu（deb 包的 Depends 已覆盖，手动解包时需要）
sudo apt install libgtk-3-0 libdbus-1-3 libepoxy0 libfontconfig1 libfribidi0 \
  libx11-6 libxi6 libatk-bridge2.0-0 libcurl4 libssl3 libsqlite3-0 liblzma5
```

AppImage 在无 FUSE 的环境可解包运行：`./ArchoeraMusic-*.AppImage --appimage-extract-and-run`。

### 1.5 macOS 提示「已损坏」或无法验证开发者

自编译产物未签名，首次运行需右键「打开」，或清除隔离属性：

```bash
xattr -dr com.apple.quarantine ArchoeraMusic.app
```

### 1.6 Windows Defender 报 `Trojan:Win32/Bearfoos.A!ml`（误报）

这是 **机器学习误报**（`!ml`），不是程序行为异常。官方 Windows 产物目前**未做
Authenticode 签名**，Defender 会依据「未签名 + 低信誉 + 原生导入/安装器形态」打分；
`archoera_music.exe` 曾被静态链接的 Rust CLI 带入 `WS2_32`/控制台/`dbghelp` 等导入，
进一步抬高了分数。

发布侧已做的收敛：GUI 主程序**不再**静态链接命令行客户端（Windows 改为转发到同目录
`archoerashell.exe`）；Release 不再包含调试器/控制台创建代码（`IsDebuggerPresent`/
`AllocConsole`）；`archoera_music.exe`、`archoerashell.exe`、`archoera-vault.exe` 与
安装器都带完整 VERSIONINFO。

用户侧处理（**不建议**直接关闭实时保护）：

1. 用发布页的 `SHA256SUMS` 与 `.sig1` 核对文件完整性；
2. 在「Windows 安全中心 → 病毒和威胁防护 → 保护历史记录」确认被隔离的具体文件；
3. 通过 <https://www.microsoft.com/en-us/wdsi/filesubmission> 提交该文件为误报
   （每个新版本哈希不同，需要重新提交）；
4. 确认来源可信后，仅对被隔离的**安装目录**添加排除项，或使用便携 zip。

长期解法是 Authenticode 代码签名 + 信誉积累；应用层的 `.sig1`/原生清单只能证明
完整性，不能替代 OS 代码签名。

## 2. 播放与音频

### 2.1 没有声音 / 声音去了别的设备

设置 →「播放」→「输出设备」：

- 默认是「系统默认」（跟随系统，引擎不会自动改道）；可显式选一个设备，切换即时或下一曲生效，
  偏好会保存。
- 设备列表可切「只看可用设备 / 显示全部设备」；`不可用` 与 `虚拟设备` 会被标注。
- 列表加载失败会提示「无法枚举音频输出设备（引擎不可用？将保持系统默认）」，此时先看 §1.1。

### 2.2 蓝牙耳机只有免提（HFP）音质

列表里带「通话/低质」标记的设备走的是免提/HFP（常见 16kHz 单声道），音乐会按语音标准播放，
部分耳机甚至无声。按提示切到 A2DP：

1. 断开蓝牙耳机后重新连接；
2. 在系统蓝牙设置里把设备切到「音频 / A2DP」（部分系统叫「媒体音频」）；
3. 若仍只有 Headset/免提，取消配对后重新配对。

应用**不会**自动改道；选择通话设备前会二次确认。

### 2.3 切换输出设备失败

会弹出「切换输出设备失败：<原因>」。常见原因是设备被独占、已被拔出、或后端拒绝格式。
先切回「系统默认」，确认设备在系统里可用后再试；持续失败请附日志中 `engine` 相关行。

### 2.4 无损 / Hi-Res 被降质

设置 →「播放」→「原音质直通（不转码）」：

- **开**（默认）：保持源采样率，Hi-Res / 无损不降质；
- **关**：统一走 48kHz 转码管线。

注意蓝牙链路本身可能重采样；HFP 模式下再高的源也无法挽回音质（见 §2.2）。

### 2.5 某个文件不能播放 / 不能入库

「能播」与「能入库」是两件事：

- **播放**由引擎（自研内核 + FFmpeg 兜底）决定；
- **入库**由扫描器的扩展名白名单决定，不在白名单的文件会被直接忽略。

完整支持矩阵见 [音频格式支持矩阵](format-support-matrix.md)。白名单外的格式可在
设置 →「扫描」→「追加扩展名」里补充（空格或逗号分隔）。受 DRM 保护的文件（如 Audible）不在支持范围。

### 2.6 切输出设备后开头 1~4 秒被跳过

已在 1.0.1+2 之后的主线修复（切换设备时不再丢弃预解码缓冲），更新到后续版本即可；
旧版可手动重新播放该曲绕过。

### 2.7 频谱 / 可视化不显示

- 设置 →「播放」→「频谱可视化」需开启；
- 频谱依赖引擎的 FFT 分析库；引擎不可用时不会渲染（见 §1.1）；
- 全屏播放页的水纹 / 流体背景另有开关（见 §10）。

### 2.8 变速、EQ、响度归一化

- 变速不变调在 设置 →「音频效果」→ 播放速度（不影响音高）；
- EQ / 限幅 / 响度归一化也在「音频效果」；
- 响度归一化若没有测量数据，只使用文件内的 ReplayGain 标签；需要逐曲测量时在
  设置 →「扫描」打开「扫描时分析响度」（较慢，已入库曲目需全量重扫）。

### 2.9 设备只有左/右一侧发声

单只耳机、单声道音箱或接线只到一侧时，立体声内容会有一边听不到。可在
设置 →「音频效果」→「声道」打开**多声道合并**：引擎会把所有声道按等功率合并为
单声道并送到每个输出声道，两侧都能听到完整内容。

- 默认关闭；正常立体声设备建议保持关闭（关闭时逐位旁通，不改变原声）；
- 合并后声场会收窄为单声道，这是预期行为；
- 若设备本身在系统里被识别为单声道，引擎也会自动完成必要下混，此时该开关不是必需的。

### 2.10 某个在线源提示「证书校验失败」/ 无法播放

播放引擎（自研内核与 FFmpeg）都用**系统信任库**校验 https。出现证书类失败时，
内核会返回两个可区分的状态码：

- `9` 证书被拒：链不受信任 / 主机名不符 / 已过期；
- `10` 没有可用信任库：系统 CA 文件缺失或全部不可读。

处理逻辑（自动）：

1. 发现 `9/10` 后，应用会改走 **Dart 整曲下载**再解码——Dart SDK 的根证书是
   编译进运行时的，与系统 CA 目录布局、系统更新完全无关；成功后正常播放
   （起播会比直连稍慢，属预期）；
2. 整曲下载不可用（超过内存门禁 / 下载失败）时才会报错，不再静默跳歌。

仍无法播放时可以手动指定信任源（内核与 FFmpeg 都认，优先级最高）：

```bash
SSL_CERT_FILE=/path/to/ca-bundle.pem ./archoera_music
SSL_CERT_DIR=/path/to/certs            # 目录列表，`:` 分隔
```

自托管 Subsonic / Jellyfin 用 https + 自签证书时，请把该证书导入系统信任库
（或使用上面的环境变量）；应用**不会**跳过证书校验。

## 3. 本地曲库与扫描

### 3.1 扫描不到歌曲

按顺序检查：

1. **扫描目录**是否包含该文件夹（符号链接 / 挂载点是否可读）；
2. **扩展名**是否在扫描器白名单内（见 [格式矩阵](format-support-matrix.md)），或已在
   设置 →「扫描」→「追加扩展名」里补充；
3. **文件大小**是否超过「单文件大小上限（MB）」；
4. **文件数**是否超过「最大扫描文件数」；
5. 文件是否已被移入隔离区（§3.2）；
6. 大目录扫描是否因「连续错误上限」提前中止（调高或修复坏文件后重扫）。

### 3.2 文件被移进「隔离区」

连续解析失败 ≥3 次的文件会被移入隔离目录，避免反复拖慢扫描。设置 →「扫描」里可查看、
打开目录、单个删除或清空。确认文件本身损坏后再删除；**清空不可恢复**。

### 3.3 封面 / 元数据缺失

- 扫描器优先读文件内标签（TagLib / 自研内核直桥），没有标签时不会凭空生成；
- 可用「刮削」补全在线元数据（设置 →「刮削」）；
- 部分容器（如 `.tta` / `.spx`）没有 TagLib 元数据，依赖内核元数据直桥，信息可能较少；
- 内嵌封面损坏时可能只显示占位图，可用外部工具重写标签后再扫描。

### 3.4 扫描很慢

- 「扫描并行度」默认 0=自动；机械盘 / 网络盘上过高的并行度反而更慢，可手动调低；
- 「扫描时分析响度」会逐曲解码，显著变慢；不需要响度归一化时关闭；
- 「批大小」影响数据库写入频率，默认自动即可；
- 首次扫描要建库 + 提元数据，后续增量扫描会快很多。

### 3.5 曲库“消失”或路径变了

曲库记录的是扫描时看到的文件路径（通常为绝对路径）。移动 / 重命名音乐目录后需要重新添加扫描目录并扫描；
换机器或改挂载点时，建议保持相同路径，或迁移后重扫。数据库文件位置可在
设置 →「存储」里看到。

## 4. 本地搜索

- 默认只做**基础搜索**（标题 / 歌手 / 专辑），不建索引、零磁盘占用。
- 需要按相关度搜歌词 / 元数据 / 拼音时，在 设置 →「本地搜索」打开总开关：
  后台构建索引，首次构建耗时且占磁盘（万首约数百 MB）。
- 索引状态会显示「未启用 / 正在构建 / 就绪 / 不可用」。构建失败会**自动回退基础搜索**，
  原因见状态行与日志；可「重建索引」或「删除索引」后重来。
- 想让同名 `.lrc` 侧车歌词也参与搜索，需额外打开「索引 .lrc 侧车歌词」。

## 5. 歌词

### 5.1 没有歌词

- 设置 →「歌词」→「歌词来源顺序」：当前平台没有歌词时，按你排的顺序回退到其它平台；
- 「歌词格式顺序」：优先逐字还是标准歌词；
- 在线 TTML 歌词（Beta）会从 AMLL DB 拉取逐字歌词，**需要联网**，命中后覆盖平台歌词；
- 本地曲目可放同名 `.lrc` 侧车文件（与音频同目录、同文件名），扫描时写入曲库；
  另有 `<name>.trans.lrc`（译文）与 `<name>.romaji.lrc`（音译）。**新加的 `.lrc` 需要重新扫描**
  该目录后才会出现。

### 5.2 歌词不同步 / 有奇怪的行

- 逐字歌词与标准歌词的精度不同，可在「歌词格式顺序」里换优先级；
- 可用「歌词排除」按关键词或正则隐藏特定行（如制作人员名单），关键词不区分大小写；
- 歌词墙（AMLL 风）与经典引擎可在 设置 →「歌词」→「引擎」切换，仅影响全屏播放器。

### 5.3 歌词界面卡顿

歌词墙整墙滚动开销略高。可切回经典引擎；模糊效果也可用环境变量降级：
`ARCHOERA_LYRICS_BLUR=off`（或 `perline` / `panel`）。

## 6. 在线音源与登录

- 内置网易云 / 酷狗 / QQ 音乐；登录态与 Cookie 存在凭据保险库（见 §9）。
- **登录失效**：重新登录即可。若提示凭据库无法解锁，先按 §9 处理。
- **429 / 请求过于频繁**：平台风控。降低操作频率，避免短时间大量搜索 / 切歌；
  QQ 音乐有额外的退避策略。
- **播放失败**：部分平台允许自动换源（搜索另一平台的同名曲重试），日志里会出现
  `自动换源: …`；本地曲目与流媒体不参与自动换源。
- **实验性音源（NekoMusic）**：默认关闭，在 设置 →「实验性音源」启用。它是第三方非官方接入，
  只支持登录（不提供注册 / VIP 开通），接口可能随时失效；启用后搜索 / 我喜欢 / 收藏里会出现 `NK`。

## 7. 下载

### 7.1 提示「下载引擎初始化失败」

原生下载库未加载或初始化失败（错误里带 code）。先按 §1.1 确认 `native/` 完整；仍失败请附日志中
`downloader` 相关行。

### 7.2 解析失败 / 下载中断

- 酷狗 / 网易云在 Rust 解析失败时会自动回退到播放管线解析 URL 后重试（日志可见回退记录）；
- 预解析 URL 会过期，「重试」会重新解析，不要复用旧任务参数；
- 网络切换、代理、平台风控都可能导致中断；可先暂停再继续（支持续传）。

### 7.3 下载很慢 / 被限速

- 设置 →「下载」→「同时下载数」1~5，过多会互相抢带宽；
- 「下载限速」可按需设置；
- 平台侧限速无法绕过；「动态设备指纹」默认关闭，开启后每次启动随机设备标识，
  **可能触发平台风控**，不建议常开。

### 7.4 文件名 / 目录不符合预期

- 「文件名模板」支持 `<artist>` / `<title>` / `<album>`，只影响**之后入队**的任务；
- 「目录分组」决定按专辑 / 歌手等分组；
- 「下载记录上限」10~500，超限只淘汰最旧的失败 / 已取消记录，进行中任务不受影响。

---

## 8. 流媒体（Subsonic / Jellyfin / Emby）

- 设置 →「媒体源」添加服务器；Subsonic 默认端口 4533，Jellyfin 默认 8096（留空自动匹配）。
- 「测试连接」失败时按错误分类排查：
  - **鉴权失败**（401/403、Subsonic 40–44）：账号 / 密码 / API 令牌错误，或服务端禁用了该用户；
  - **网络 / 超时**：地址、端口、防火墙、反向代理、HTTPS 证书；
  - **协议错误**：服务端返回了非预期结构（版本不兼容 / 反向代理改写了响应）。
- 音质档位「高 / 中 / 低」会请求服务端**转码为 MP3**，需服务端支持；不支持时会退回原文件。
- 封面 / 头像由全局 HTTP 客户端拉取，若服务端要求特殊请求头或自签证书，可能显示不出来。
- 内置 Subsonic 服务端可在「媒体源」里直接添加（本机媒体库），无需外部服务器。

## 9. 凭据保险库

凭据（登录态、流媒体密码、本地 Subsonic 账号）由独立进程 `archoera-vault` 加密存储。
可选方案：`crypto`（默认，主密钥放系统安全存储）、`file`（文件密钥，无头 / 无钥匙串环境）、
以及 slots 的 `m1`（口令）/ `m2a`（口令 + 设备 + 恢复码）/ `m2b`（仅设备，本机免密，较弱）。

### 9.1 忘记口令

口令无法找回：`m1` 只能销毁重建；`m2a` 有恢复码时可用恢复码解锁。销毁会同时清掉保险库文件、
备份与设备密钥，**不可恢复**，之后需重新登录各平台。

### 9.2 换机 / 设备变更后提示需要恢复

`m2a` 的设备因子失效时会进入恢复流程，用当初保存的**一次性恢复码**解锁。没有恢复码则只能销毁重建。
`m2b` 没有口令也没有恢复码，设备密钥丢失即无法解密。

### 9.3 提示「份额不配对」

保险库文件与系统钥匙串里的份额不匹配（换过系统账户、迁移过数据目录、或份额被删）。
本地凭据无法解密，需按提示「销毁重建」后重新登录。

### 9.4 Linux 上没有可用的系统钥匙串

无桌面会话 / 没有 Secret Service（libsecret）时，`crypto` 方案无法使用。改用 `file` 后端
（文件密钥）或 slots 方案（自包含，不依赖钥匙串）。不要在没有钥匙串的机器上强行选系统保护。

### 9.5 解锁失败被锁定

连续解锁失败会按 1s → 2s → … → 5min 退避，锁定期间直接拒绝。等待即可；退避**不是**安全边界，
真正的强度来自 KDF 档位与口令 / 恢复码熵。注意调高档位会让解锁更慢、更吃内存。

### 9.6 切换加密方案后为什么要重启

切换会重建容器并涉及各模块的凭据状态，应用会提示重启。重启后若为口令模式，需要先解锁；
解锁前登录态与流媒体凭据显示为未登录，播放与下载会中断。

## 10. 性能、渲染与内存

- **播放页卡顿 / 掉帧**：设置 →「性能 / 渲染」可关闭「水纹 GPU 着色器」（回退 CPU 网格），
  或开启「动态层半分辨率」「损伤区裁剪」（仅 CPU 回退路径生效）。
  也可用环境变量强制回退：`ARCHOERA_RIPPLE_SHADER=0`、`ARCHOERA_FLUID_SHADER=0`。
- **歌词区开销**：歌词墙比经典引擎重；模糊效果可关（`ARCHOERA_LYRICS_BLUR=off`）。
- **频谱**：播放时持续渲染，低端设备可关闭（设置 →「播放」）。
- **内存高**：设置 →「存储」里可清缓存或设置歌词 / 封面缓存上限。取消上限会让缓存无限制占用内存，
  可能造成卡顿，应用会二次确认。
- **日志占空间**：日志恒为单文件、上限 4 MiB；不需要落盘时在 设置 →「存储」关闭。

## 11. 平台集成（托盘 / 媒体键 / 防休眠 / 深链）

这些能力由平台桥接提供，缺失时**静默降级**（功能消失但不影响播放）；执行失败会 toast 告警。

- **系统媒体会话**（MPRIS / SMTC / Now Playing）可在设置里关闭；媒体键无效时先确认该开关与
  桌面环境的媒体键绑定。
- **防休眠**：播放时阻止息屏 / 休眠；被系统策略拒绝时会提示，属系统限制。
- **托盘**：部分 Linux 桌面需要扩展（如 AppIndicator）才显示托盘图标。
- **深链**：`archoera://` 由系统注册后唤醒应用（如 `archoera://search?q=关键词`）；
  Linux 下需桌面环境正确注册 scheme，否则链接不会交给应用。

## 12. 数据、备份与迁移

| 想做的事 | 做法 |
|---|---|
| 换数据目录 / 做便携版 | 设 `ARCHOERA_DATA_DIR` 指向新目录后启动 |
| 备份 | 备份整个数据目录（含曲库 DB、偏好、`vault` 文件与 `device.key`）；**备份含凭据，注意保管** |
| 清缓存 | 设置 →「存储」→ 缓存（不影响曲库、历史、账号） |
| 删搜索索引 | 设置 →「本地搜索」→ 删除索引（下次搜索重建） |
| 彻底卸载 | 卸载应用后手动删除数据目录；凭据库文件与 `device.key` 需一并删除 |
| 销毁敏感数据 | 设置 →「存储」→ 安全销毁（覆盖写入并删除，不可恢复） |

> 迁移后若曲库为空，是路径变了（§3.5）；若凭据不可用，是保险库与系统份额 / 设备密钥不匹配（§9）。

## 13. 其他

### 13.1 MCP 控制服务连不上

- 默认**关闭**：设置 →「MCP 接入」打开总开关后才会监听；
- 只监听本机回环 `127.0.0.1`，端口范围 1024~65535，改端口会自动重启监听；
- 请求需要「访问密钥」（可在设置里复制 / 重新生成），密钥错误会被拒绝；
- 各项能力默认关闭，需要按组开启；关闭总开关即停止监听。
- 细节与接口见 [MCP 文档](mcp.md)。

### 13.2 开发者模式 / 更多诊断项

设置 →「关于」长按「版本」约 10 秒可开启开发者模式，之后设置里会出现「开发者」分类
（开发者模式开关、FPS 监视、下载模块开关等）。反馈问题时可按需开启，但不要把含凭据的原始数据公开。

## 14. 环境变量速查

| 变量 | 作用 |
|---|---|
| `ARCHOERA_DATA_DIR` | 覆盖数据目录（DB / 偏好 / 日志 / 保险库） |
| `ARCHOERA_LOG_LEVEL` | 日志级别：`debug` / `info` / `warn` / `error` / `fatal` |
| `ARCHOERA_NATIVE_DIR` | 开发态：原生库搜索目录（完整性校验不读它） |
| `ARCHOERA_AUDIO_ENGINE` / `ARCHOERA_SCANNER_FFI` / `ARCHOERA_INDEXER_FFI` / `ARCHOERA_DOWNLOADER_SO` / `ARCHOERA_PLATFORM_BRIDGE` | 精确指定单个原生库路径或所在目录 |
| `ARCHOERA_VAULT_BIN` | 指定 `archoera-vault` 可执行文件 |
| `ARCHOERA_RIPPLE_SHADER=0` | 关闭水纹 GPU 着色器（回退 CPU 网格） |
| `ARCHOERA_FLUID_SHADER=0` | 关闭流体背景着色器 |
| `ARCHOERA_LYRICS_BLUR` | 歌词模糊：`perline` / `panel` / `off` |
| `ARCHOERA_EVENT_POLL_FALLBACK=1` | 引擎事件回退到 50ms 轮询（排查推送问题） |

> 环境变量是排障 / 开发用的后门，不是正式设置项；优先用设置页。
