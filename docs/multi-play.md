# 多重奏（multi-play）

> 2026-11-06 · 设置 →「音频效果」→「多重奏」

## 是什么

把**同一首歌**复制成 N 份，在几乎同一时刻开始播放，但每份相对前一份错开一个
固定的起始间隔（10–3000 ms）。听感类似多台播放器/多轨卡农叠在一起；不是变速，
也不是变调。

- **并行倍数**：1–128 份（1 = 旁通）
- **每份错开**：10–3000 ms（第 i 份延迟 `i × step`）
- **总跨度上限**：`(份数 - 1) × 错开 ≤ 60 s`。份数越多，可用错开越小
  （例如 4 份可用满 3000 ms；128 份时每份最多 472 ms）。设置页的错开滑块
  会按当前份数自动收敛。
- 默认：关闭 / 4 份 / 20 ms

## 实现方式

不是启动 N 个解码器或 N 个输出设备，而是在**同一个流式播放器**里：

1. 解码仍然只做一次（内存播放模式，默认开启）；
2. 设备音频回调把当前 PCM 追加到历史环；
3. 对每个输出帧，按 `base - i × step` 从历史环抽取 N 个延迟抽头并求和；
4. 混音后按 `0.85 / sqrt(N)` 缩放并硬限幅，再应用会话音量。

历史环容量按“当前最远延迟 + 0.5 s 余量”向上取 2 的幂，最小 8 秒、最多约
64 秒（受 60 s 总跨度上限约束）：

| 总跨度 | 立体声 48 kHz 历史环 |
| --- | --- |
| ≤ 8 s | 约 3 MB |
| 20 s | 约 8 MB |
| 60 s | 约 25 MB |

因此内存里只有一份 PCM + 一个历史环（不会按份数线性增长），CPU 主要花在
`O(N)` 的抽头求和上；128 份在 48 kHz 立体声下约 1200 万次乘加/秒，属于可控
但明显的负载。

运行中把错开/份数调大到超出当前历史环容量时，引擎会在引擎线程里扩容：
先短暂停止设备（约几毫秒），把旧历史按绝对位置迁入新环后再启动，延迟副本
不会突然读到静音。缩小参数不会立即释放内存（下一次 seek/切档或停止播放时
复位）。

## 限制与风险

- **仅内存/流式播放模式生效**。文件播放模式（设置里关闭「内存播放」）会忽略
  该效果，因为文件模式走 `ma_sound` 直接播放整段解码结果。
- 高倍数会显著增加 CPU 与延迟混音的计算量，大跨度会增加内存。设置页在
  `倍数 > CPU 线程数`、`倍数 ≥ 64` 或 `总跨度 ≥ 30 s` 时显示红色警告。
- 所有副本共用同一路解码，因此不存在 N 份独立解码带来的音画不同步；但也
  不是严格意义上的 N 个独立播放器（seek/暂停/切歌是统一的）。
- 曲尾会把最长延迟的尾巴排空后再结束，避免最后一截副本被截断；跨度很大时
  曲尾会相应延长。
- seek / 切档会重建历史环（旧延迟内容丢弃），这是预期行为。

## 命令

Dart → 引擎：

```json
{"type":"set_chorus","enabled":true,"voices":8,"step_ms":1500}
```

- `enabled=false` 或 `voices<=1` 时无损旁通。
- `step_ms` 收敛到 10–3000；总跨度超过 60 s 时引擎按当前份数自动减小实际错开
  （与设置页滑块上限一致）。
- 引擎在 player 尚未创建时会先缓存参数，流式播放器建好后立即应用。
- 独立 CLI（`archoera-audio-engine` 的 stdin 控制）也接受同一命令（即时生效，不持久化）。
