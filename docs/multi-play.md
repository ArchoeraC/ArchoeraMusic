# 多重奏（multi-play）

> 2026-11-06 · 设置 →「音频效果」→「多重奏」

## 是什么

把**同一首歌**复制成 N 份，在几乎同一时刻开始播放，但每份相对前一份错开一个极小的
起始间隔（10–50 ms）。听感类似多台播放器/多轨卡农叠在一起；不是变速，也不是变调。

- **并行倍数**：1–128 份（1 = 旁通）
- **每份错开**：10–50 ms（第 i 份延迟 `i × step`；128 份 × 50 ms 时总跨度约 6.35 s）
- 默认：关闭 / 4 份 / 20 ms

## 实现方式

不是启动 N 个解码器或 N 个输出设备，而是在**同一个流式播放器**里：

1. 解码仍然只做一次（内存播放模式，默认开启）；
2. 设备音频回调把当前 PCM 追加到一段约 8 秒的历史环；
3. 对每个输出帧，按 `base - i × step` 从历史环抽取 N 个延迟抽头并求和；
4. 混音后按 `0.85 / sqrt(N)` 缩放并硬限幅，再应用会话音量。

因此内存里只有一份 PCM + 一个历史环，CPU 主要花在 `O(N)` 的抽头求和上；
128 份在 48 kHz 立体声下约 1200 万次乘加/秒，属于可控但明显的负载。

## 限制与风险

- **仅内存/流式播放模式生效**。文件播放模式（设置里关闭「内存播放」）会忽略
  该效果，因为文件模式走 `ma_sound` 直接播放整段解码结果。
- 高倍数会显著增加 CPU 与延迟混音的计算量。设置页在
  `倍数 > CPU 线程数`、`倍数 ≥ 64` 或 `总跨度 ≥ 1000 ms` 时显示红色警告。
- 所有副本共用同一路解码，因此不存在 N 份独立解码带来的音画不同步；但也
  不是严格意义上的 N 个独立播放器（seek/暂停/切歌是统一的）。
- 曲尾会把最长延迟的尾巴排空后再结束，避免最后一截副本被截断。
- seek / 切档会重建历史环（旧延迟内容丢弃），这是预期行为。

## 命令

Dart → 引擎：

```json
{"type":"set_chorus","enabled":true,"voices":8,"step_ms":20}
```

- `enabled=false` 或 `voices<=1` 时无损旁通。
- 引擎在 player 尚未创建时会先缓存参数，流式播放器建好后立即应用。
- 独立 CLI（`archoera-audio-engine` 的 stdin 控制）也接受同一命令（即时生效，不持久化）。
