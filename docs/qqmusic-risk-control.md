# QM 平台接口与限流观察（摘要）

> 目的：记录与平台交互时的**稳定性经验**，避免账号被误判。具体实现见
> `app/lib/apis/qqmusic/` 与 `app/lib/services/qqmusic/`。本文不展开第三方实现的
> 设备档案、签名或验证细节。

## 结论

- **稳定身份 + 一致出口 + 合理节奏**，比任何“签名技巧”更重要。
- **批量请求要限流**：搜索/取流/详情并发要小，失败按退避重试；短时间高频请求
  容易触发账号级限流。
- **分页与音质档位以接口实际返回为准**，不硬编码过时档位或过大的页尺寸。
- **验证交给官方客户端**：触发安全验证时提示用户到官方客户端完成，应用内
  **不伪造**设备档案或验证材料。
- **接口会变**：参数与端点以线上实测为准，变更前先小流量确认。

## 实现位置

| 能力 | 位置 |
| --- | --- |
| 请求与签名封装 | `app/lib/apis/qqmusic/core/` |
| 歌单/收藏/我喜欢 | `app/lib/apis/qqmusic/modules/` |
| 限流与错误归类 | 请求层 + 各模块调用方 |

## 维护约定

- 平台接口变更先小流量验证，再更新本文结论与实现；
- 不记录、不提交账号凭据、设备档案或验证材料；
- 新增批量接口时同步评估并发与页数上限。
